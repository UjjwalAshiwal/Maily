# API (Phase 9)

- `GET /health` → `{ ok, postgres: "up"|"down", redis: "up"|"down" }`
  - 200 when both reachable, 503 otherwise. Server stays up either way.
- `POST /api/emails/schedule { senderId, recipient, subject, body, scheduledAt }`
  - 201 → `{ emailId, jobId, status: "SCHEDULED" }`
  - 400 invalid fields / bad email / past `scheduledAt`; 404 unknown sender.
  - Creates the Email row, enqueues a BullMQ delayed job (`delay = scheduledAt - now`, `jobId = email-<id>`), stores `bullJobId`. Enqueue failure marks the email FAILED, never orphaned SCHEDULED.
- `GET /api/emails?status=&page=&limit=` (protected, Phase 9)
  - 200 → `{ results: [{ id, senderId, senderEmail, recipient, subject, status, scheduledAt, sentAt }], total, page, limit }`
  - PostgreSQL-authoritative list scoped to the caller's senders via the relation (no client senderId, no ES). `status` optional (400 on invalid); `page`/`limit` clamped, max 100.
- `GET /api/senders` (protected)
  - 200 → `{ senders: [{ id, email }] }` — the caller's live senders, the only valid `senderId` values for scheduling.
- `GET /api/emails/search?q=john&status=SENT&page=1&limit=20`
  - 200 → `{ results: [{ id, senderId, recipient, subject, status, scheduledAt, sentAt }], total }`
  - Empty/missing `q` → empty result (no match-all). Max `limit` 100. Elasticsearch first, Postgres ILIKE fallback when ES is down (never 500).
- Auth (all `/api/emails` routes require `Authorization: Bearer <token>`):
  - `GET /api/auth/google` → 302 to Google (starts OAuth, state in Redis).
  - `GET /api/auth/google/callback?code&state` → 302 to `{FRONTEND_URL}/auth/callback?token=…` (or `/login?error=oauth_failed`).
  - `GET /api/auth/me` (protected) → `{ user: { id, email, name, avatarUrl } }`.
  - `POST /api/auth/logout` → `{ ok: true }` (stateless: client discards token).
- Slack (`/connect`, `/status`, `/disconnect` require Bearer token; `/callback` is public via one-time state):
  - `GET /api/slack/connect` → 302 to Slack (starts OAuth, user-bound state in Redis).
  - `GET /api/slack/callback?code&state` → 302 to `{FRONTEND_URL}/settings?slack=connected` (or `?slack=error`). Upserts encrypted connection, never duplicates.
  - `GET /api/slack/status` (protected) → `{ connected: false }` or `{ connected: true, teamId, connectedAt }` (never the credential).
  - `POST /api/slack/disconnect` (protected) → `{ ok: true }`; stops notifications, allows reconnect.
- Bull Board (development-only, no login; set `BULL_BOARD_ENABLED=false` to unmount):
  - `GET /admin/queues` → dashboard UI for the live `email-send` queue (waiting/active/delayed/completed/failed).
